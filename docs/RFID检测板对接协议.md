# RFID 检测板 对接协议

> **版本**：v1.0  ｜ **更新**：2026-11-16  ｜ **对接方**：MES 后端（京嵘 MES 系统）

本文档面向 RFID 桌面检测板的固件/软件开发人员，描述检测板与 MES 系统的接口契约。

---

## 1. 接口总览

| 项目 | 值 |
|---|---|
| **请求方法** | `POST` |
| **请求地址** | `http://<MES服务器IP>:8080/api/epc` |
| **生产地址** | `http://47.96.120.150:8080/api/epc` |
| **Content-Type** | `application/json` |
| **请求体** | JSON 数组（EPC 字符串列表） |
| **响应体** | `{"ok": true}` 或 `{"ok": false}` |

检测板每次读取到衣服（含瑕疵夹）时，把**一次读取的全部 EPC**打包成一个数组，发一次请求即可。MES 自动完成分类、落库、状态流转。

---

## 2. 请求

### 2.1 请求头

```
POST /api/epc HTTP/1.1
Host: 47.96.120.150:8080
Content-Type: application/json
X-Device-Id: RFID-PLATE-001
```

| 请求头 | 必填 | 说明 |
|---|---|---|
| `Content-Type` | 是 | 固定 `application/json` |
| `X-Device-Id` | 推荐 | 检测板设备 ID，MES 据此识别工位/工序/检验员。每台检测板在 MES 管理界面注册后获得唯一 ID（如 `RFID-PLATE-001`）。缺省时回落 `RFID-PLATE-001`。 |

### 2.2 请求体

请求体是一个 **JSON 字符串数组**，包含本次读取到的所有 EPC，混合在一起即可：

```json
["E476FD0154554848B4D3D182", "X-D005-007", "X-D001-012"]
```

数组里有两类 EPC，MES 按**前缀自动分类**：

| 类型 | 格式 | 示例 | 数量 |
|---|---|---|---|
| **衣物水洗唛 RFID** | 任意非 `X-` 开头的 EPC | `E476FD0154554848B4D3D182` | **必须有且仅有 1 个** |
| **瑕疵夹 EPC** | `X-{类型码}-{序号}` | `X-D005-007` | 0 到 N 个 |

> **EPC 建议统一大写**，与 MES 已注册的瑕疵夹 EPC 保持一致。

### 2.3 请求示例

**场景 A：检出瑕疵（衣服有问题）**

衣服平铺到检测板，读到 1 个水洗唛 + 2 个瑕疵夹：
```json
["E476FD0154554848B4D3D182", "X-D005-007", "X-D001-012"]
```

**场景 B：合格件 / 修补完成**

衣服无瑕疵夹，或修补完成取下夹子后再放检测板，只读到水洗唛：
```json
["E476FD0154554848B4D3D182"]
```

## 3. 响应

### 3.1 正常响应（HTTP 200）

```json
{"ok": true}
```
或
```json
{"ok": false}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | boolean | `true` = 处理成功；`false` = 处理失败（如衣物未绑码、读到多件衣物等） |

**检测板只需根据 `ok` 判断成功/失败**。失败的具体原因由 MES 服务端记录在日志里，不在响应体中返回。

### 3.2 建议的反馈动作

| `ok` 值 | 含义 | 检测板反馈建议 |
|---|---|---|
| `true` | 读取并处理成功 | 绿灯 / 提示音"已记录" |
| `false` | 处理失败 | 红灯 / 提示音"失败"，等待重新放置或人工处理 |

> **不需要根据返回值区分**"合格/不合格/修补中"等业务状态，MES 服务端会自动维护衣服状态。检测板只管"有没有成功上报"。

### 3.3 异常响应

| HTTP 状态码 | 含义 | 检测板处理 |
|---|---|---|
| `200` | 已处理，看 `ok` 字段 | 按 `ok` 反馈 |
| `400` | 请求体格式错误（非 JSON 数组、空数组等） | 检查请求体格式 |
| `5xx` | MES 服务端异常 | 重试（建议指数退避，最多 3 次） |

---

## 4. 业务规则（供开发理解，检测板无需实现）

检测板只要正确发送 EPC 数组即可，以下逻辑全部由 MES 服务端处理：

1. **EPC 分类**：`X-` 开头 → 瑕疵夹；其余 → 衣物水洗唛。
2. **衣物定位**：按水洗唛 RFID 查 MES 的衣服档案（`t_garment`），未绑码或已拆标 → `ok:false`。
3. **瑕疵匹配**：每个瑕疵夹 EPC 查 MES 瑕疵夹主档（`t_defect_clip`），匹配出瑕疵类型。
4. **状态流转**：
   - 有瑕疵夹 → 衣服进入"修补中"状态，等待修补
   - 无瑕疵夹 且 衣服原本在"修补中" → 标记修补完成，恢复正常流转
   - 无瑕疵夹 且 衣服正常 → 普通合格件
5. **幂等**：MES 服务端自动生成批次号，重复推送同一批 EPC 不会重复记录。

---

## 5. 上报时机

| 事件 | 是否上报 | 说明 |
|---|---|---|
| 衣服平铺到检测板，读取到 EPC | **上报** | 一次放置 = 一次请求，包含本次读到的全部 EPC |
| 衣服离开检测板 | 不上报 | 只在"读到"时上报一次 |
| 连续读取到同一批 EPC（未拿走） | 可不重复上报 | MES 有幂等保护，但建议检测板做去抖（如 2 秒内同批不重发） |

## 6. 调试与联调

### 6.1 curl 测试命令

```bash
# 成功用例（衣物 RFID + 1 个瑕疵夹）
curl -X POST http://47.96.120.150:8080/api/epc \
  -H "Content-Type: application/json" \
  -H "X-Device-Id: RFID-PLATE-001" \
  -d '["E476FD0154554848B4D3D182", "X-D001-001"]'
# 预期响应：{"ok":true}

# 失败用例（衣物未绑码）
curl -X POST http://47.96.120.150:8080/api/epc \
  -H "Content-Type: application/json" \
  -H "X-Device-Id: RFID-PLATE-001" \
  -d '["NOT-EXIST-RFID-0000"]'
# 预期响应：{"ok":false}
```

### 6.2 参考实现（Python）

仓库根目录的 `rfid_server.py` 是 MES 提供的测试接收端，契约与本协议完全一致。检测板开发时可以先用它本地联调，确认请求格式无误后再切换到正式 MES 地址：

```python
import requests
resp = requests.post(
    "http://47.96.120.150:8080/api/epc",
    headers={
        "Content-Type": "application/json",
        "X-Device-Id": "RFID-PLATE-001",
    },
    json=["E476FD0154554848B4D3D182", "X-D005-007"],
    timeout=10,
)
print(resp.json())  # {"ok": true}
```

### 6.3 MES 已注册的测试数据

| 类型 | 值 | 说明 |
|---|---|---|
| 检测板设备 ID | `RFID-PLATE-001` | 已绑成检工位，工序 P070，检验员 EMP070 |
| 测试衣物 RFID | `E476FD0154554848B4D3D182` | 已绑码，工单 06-31206-312 |
| 瑕疵夹 EPC（示例） | `X-D001-001` ~ `X-D020-005` | 共 100 个，每类 5 个，格式 `X-D{类型码}-{三位序号}` |

## 7. 约束与边界

- **单次请求只允许 1 件衣物**：检测板需保证一次只读一件衣服（物理屏蔽或限区天线）。若读到多个水洗唛 RFID 且有瑕疵夹，MES 返回 `ok:false`（无法判断夹子归属哪件）。
- **请求超时建议**：10 秒。
- **重试策略**：网络异常（超时/5xx）建议重试，最多 3 次，指数退避；业务失败（`ok:false`）**不要重试**，因为重试结果一样。
- **字符编码**：UTF-8。
- **HTTP 版本**：HTTP/1.1，支持 keep-alive。
