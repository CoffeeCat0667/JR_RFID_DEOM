# RFID EPC 采集上传工具

通过串口连接 E310 系列 UHF 读写器，读取标签 EPC 并批量 POST 到指定 HTTP 地址。

## 功能

- 扫描并列出当前电脑的串口设备，波特率可选 9600 ~ 921600（默认 115200）。
- 连接后发送 `BB 00 03 00 01 00 04 7E` 读取硬件版本，成功则显示在界面；失败弹窗提示并允许重新选择串口/波特率。
- 每 100ms 发送一次单次轮询指令 `BB 00 22 00 00 22 7E`，解析通知帧中的 EPC 与 RSSI。
- 接收缓冲区出现数据后等待 2 秒静默窗口，期间同一次放置的标签合并成一批再 POST，成功后清空该批数据。
- 每批内同一 EPC 只保留一条（保留该批最新的 RSSI）；重复读到同一 EPC 不会延长 2 秒等待。
- 首次识别到新的唯一 EPC 时读取其 TID（依次尝试 8/6/4/2 word，取实际读到的长度），在采集页与写入页的标签表中显示；读取失败时显示 `—`，每 3 秒自动重试一次（单次最多等 0.3 秒），标签拿近后会自动补读成功。
- 请求头带 `X-Device-Id`（采集页“设备 ID”，默认 `RFID-PLATE-001`）；只有 HTTP 2xx 且响应 `{"ok": true}` 才算成功。
- 网络异常或 5xx 重试 3 次（间隔 0.5s / 1s / 2s），最终失败则把整批数据放回缓冲区；`{"ok": false}` 或 4xx 不重试，直接丢弃该批。
- “写入”页可选中已识别的标签，输入 2~30 字节的新 EPC 写入标签 EPC 区并回读校验；PC 按新长度自动计算，CRC 由标签自动更新。
- 日志、配置保存在本机，最近标签在界面中显示。

## 部署（目标电脑）

1. 把 `dist\RFID_EPC_Uploader.exe` 拷贝到任意目录，双击运行。
2. 目标电脑无需安装 Python、pyserial 或任何运行时；串口驱动按设备厂商要求安装。
3. 首次运行若被 SmartScreen 拦截，选择“更多信息 → 仍要运行”。

## 从源码运行 / 打包

```bat
python -m pip install -r requirements.txt
python -m app.main
```

打包（产物 `dist\RFID_EPC_Uploader.exe`）：

```bat
build.bat
```

## 使用步骤

1. 连接读写器，选择串口与波特率，点击“刷新”可重新扫描。
2. 填写 HTTP 目标地址，例如 `http://192.168.1.100:8080/api/epc`，以及设备 ID（默认 `RFID-PLATE-001`）。
3. 点击“开始采集”。
4. 硬件版本读取成功后状态显示“采集中”，贴卡即可看到 EPC 与上传结果。
5. 点击“停止”结束采集并释放串口。

## 写入页

用于把标签的 **EPC 替换为新值**（写 EPC 区 `MemBank=01`，从 word1 写入 PC + 新 EPC），不影响采集与 HTTP 上报流程。

1. 先在“采集”页开始采集，再到“写入”页。
2. 在“识别到的标签（唯一）”表中选中目标标签（表格同时显示已读取的 TID）。
3. 输入新的 EPC，每个字节两位十六进制、空格分隔，例如：
   `E2 00 34 12 AA BB CC DD`
4. 点击“写入”。写入与回读期间后台轮询暂停，完成后自动恢复。

约束与行为：

- 输入长度需为 **2~30 字节且是偶数**（同时受 Select 掩码与 `0x49` 单次 32 word 上限约束）。
- 写入内容为 `PC + 新 EPC`：PC 高 5 位按新 EPC 字数计算（如 96 bit 对应 `0x3000`），其余标志位按 0 处理。
- EPC 区 word0 的 CRC 由标签在写入 EPC 后自动更新，程序不写 CRC。
- 写完后自动用新 EPC 重新 Select，并回读 EPC 区比对；一致才算成功。
- 写入会改变标签身份，成功后写入页表格中的 EPC 会替换为新值；此操作不可撤销。
- EPC 区容量不足或新 EPC 超过标签支持长度返回 `0xB3`，被锁定返回 `0xB4`；报错不重试。
- 回读失败或回读值与写入值不一致时报告失败，不自动重写（旧 EPC 可能已不存在，避免误写其它标签）。
- Access Password 固定 `00000000`，不发送 Access 指令；有密码的标签会写失败。
- 写入 EPC 不可撤销；界面只做文字提示，不提供备份。

## HTTP 接口约定

- 方法：`POST`
- 请求头：
  - `Content-Type: application/json`
  - `X-Device-Id: <采集页填写的设备 ID>`（留空时使用 `RFID-PLATE-001`）
- 请求体：EPC 字符串数组，大写十六进制，每批内不重复：

```json
["30751FEB705C5904E3D50D70", "E2003412AABBCCDDEEFF0011"]
```

- 成功判定：HTTP 2xx 且响应体为 `{"ok": true}`。
- `{"ok": false}`、4xx、响应不是含布尔 `ok` 的 JSON：记为失败并丢弃该批，不重试。
- 网络异常或 5xx：重试 3 次（0.5s / 1s / 2s），仍失败则整批放回缓冲区，1 秒后继续。单次请求超时 10 秒。
- 聚合：缓冲区有数据后等待 2 秒，期间新增的唯一 EPC 合并进同一批；重复读到同一 EPC 不延长等待。
- 空缓冲区不发请求。

## 本地接收验证服务器

`verify\rfid_server.py` 是单文件、仅用 Python 标准库实现的接收端，用于验证上报链路：

```bat
python verify\rfid_server.py 8000
```

- 可视化页面：`http://127.0.0.1:8000/`，每秒自动刷新。
- 上报地址：`http://<本机IP>:8000/api/epc`，与本工具默认占位地址一致。
- 展示累计条数、唯一 EPC 数、接收批次数、标签次数条形图、最近 50 批数据。
- 数据只存在内存中，重启即清空；服务监听 `0.0.0.0`，同网段电脑可直接访问。
- 与工具上报格式一致：接受 `["EPC1", "EPC2"]` 字符串数组。

如需查看 EPC + TID，可改用 `verify\rfid_server_TID.py`（原 `rfid_server.py` 保持不变）：

```bat
python verify\rfid_server_TID.py 8000
```

它同时接受 `["EPC1", "EPC2"]` 和 `[{"epc": "...", "tid": "..."}]`，页面上增加 TID 列；当前工具只上报 EPC 数组，因此 TID 列会显示 `—`。

## 常见问题

- **提示“读取硬件版本失败”**：确认串口选对、波特率与读写器一致（常见 115200 / 921600）、设备已上电且接线正确；改选后重新开始。
- **串口打不开**：串口被其他软件占用，或 USB 转串口未插好，刷新后重试。
- **读到标签但上传失败**：检查目标地址、端口、防火墙；失败数据会留在缓冲区重试，界面统计与日志会记录失败次数。
- **921600 下游标看似不满 10 次/秒**：单次 Inventory 耗时随标签数量增加，程序会跳过未完成的轮询，避免指令堆积。
